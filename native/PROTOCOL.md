# ldname.exe turbo name core: protocol (v1)
Binary snapshot "LDN1" (see SPEC.md / export_names.py). Row indexes in all responses are indexes into the exported arrays (generation G).
Server: `ldname.exe serve <names.bin> <port>` on 127.0.0.1 (TCP, UTF-8, one request per line, '\n'), many clients, request/response, connection may stay open.
Requests:
- `PING` -> `PONG`
- `LOAD<TAB><path>` -> atomically swaps in a new snapshot file; response `OK<TAB><n><TAB><gen>` (gen increments from 1); on error `ERR<TAB><message>`; searches in flight keep the old snapshot.
- `SEARCH<TAB><limit><TAB><query>` -> `OK<TAB><total_hits><TAB><truncated 0|1><TAB><gen>` then up to <limit> lines (each a row index, optionally suffixed with `?` when the row matches every predicate EXCEPT size/date because its size/mtime is unknown (-1); the client resolves those), then a line `END`. `total_hits` counts all matches (stop counting at 1,000,000). Unsupported operator (e.g. regex:) -> `ERR<TAB>unsupported<TAB><name>`.
- `STATS` -> `OK<TAB>rows=<n><TAB>gen=<g><TAB>blob_mb=<..><TAB>working_set_mb=<..>`
Query language (same meaning as localdocs_filters.py, applied to NAMES): space separated tokens; plain token = lowercase substring of the name; wildcard token containing * or ? = glob over the WHOLE name (case-insensitive, empty names never match, same backtracking rules as localdocs_filters._wildcard); ext:pdf,docx (comma list, leading dots stripped, lowercased; extension = text after last '.' or '' when no dot; invalid values are treated as plain tokens); size:>10mb size:<1kb size:5mb (units b,k,kb,m,mb,g,gb; plain number = bytes; float with '.' or ',' decimal allowed; bare value = exact equality, > and < strict; several size: tokens combine as min/max range); date:2025 date:>2026-03-01 date:<2024-06 (UTC; year/month/day granularity via calendar.timegm; bare value = inside the period [lo,hi), > means mtime >= end-of-period, < means mtime < start-of-period; invalid dates are plain tokens) ; path:<text> (substring, ordinal, of the full lowercase path built from the parent chain joined with '/', e.g. root/docs/file.txt; root with parent -1 is just its name) ; folder:<text> (substring, ordinal, of the immediate parent folder name, '' when parent is -1) ; sort:name|size|date|ext with optional leading '-' (descending; applied over ALL matches, not only the first <limit>; unknown size/mtime sort last in BOTH directions; sort:name = ordinal name, sort:ext = ordinal (ext-without-dot, name), ties keep ascending row order; invalid sort: is a plain token) ; limit:N (1..1000, overrides the request limit; limit:0 clears the override; invalid limit: is a plain token) ; file: (non-directories only) ; dir: (directories only; file: plus dir: together match nothing). Tombstoned rows (flags & 8, bit 0x80 included) never match. Without sort: ascending row order.
Details: tokenisation splits on spaces/tabs; operators are recognised only at token start (case-insensitive, value = rest of token, must be non-empty); an operator token with an unparsable value falls back to a plain/wildcard token (except regex: which always fails). Any token starting with regex: (case-insensitive, including bare 'regex:') -> the whole SEARCH fails with ERR<TAB>unsupported<TAB>regex. '?' suffix: set iff the row is returned AND (a size: predicate exists AND size[row] < 0 OR a date: predicate exists AND NOT (mtime[row] >= 0)); such rows passed every other predicate. truncated = 1 iff total_hits > number of returned row lines (also 1 whenever counting stopped at the 1,000,000 cap with rows cut off). Effective limit = spec limit:N when present else the SEARCH request limit (negative clamped to 0).
